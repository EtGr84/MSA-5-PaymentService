## Таблица-реестр транзакций Saga-оркестрации

| Транзакция | Описание | Тип | Компенсация |
| --- | --- | --- | --- |
| `COMPLETE_PAYMENT` | Зафиксировать успешное завершение платежа после перевода контрагенту. | повторяемая | - |
| `DEBIT_CUSTOMER_ACCOUNT` | Списать деньги со счета клиента или зафиксировать эквивалентную финансовую операцию списания. | компенсируемая | `REFUND_CUSTOMER` |
| `REFUND_CUSTOMER` | Вернуть клиенту ранее списанные деньги при сбое, отказе антифрода или блокировке операции. | повторяемая | - |
| `NOTIFY_CUSTOMER` | Отправить клиенту уведомление о результате платежа: успешное проведение, отказ, блокировка или возврат. | повторяемая | - |
| `NOTIFY_SECURITY` | Отправить в службу безопасности событие о подозрительной или заблокированной операции. | повторяемая | - |
| `REQUEST_FRAUD_CHECK` | Передать транзакцию в антифрод и внешние проверки; получить решение `ALLOW`, `DENY` или `MANUAL_REVIEW`. | повторяемая | - |
| `OPEN_MANUAL_REVIEW` | Создать задачу ручной проверки для оператора, если антифрод вернул `MANUAL_REVIEW`; ожидать итоговое решение не более 20 минут. | компенсируемая | `CLOSE_MANUAL_REVIEW` |
| `CREATE_PAYMENT` | Создать запись платежа, зафиксировать сумму, плательщика, получателя, идемпотентный ключ и начальное состояние Saga. | компенсируемая | `CANCEL_PAYMENT` |
| `CANCEL_PAYMENT` | Перевести платеж в финальное отмененное состояние, если процесс остановлен до необратимого перевода контрагенту. | повторяемая | - |
| `CLOSE_MANUAL_REVIEW` | Закрыть задачу ручной проверки после решения оператора, отказа, отмены платежа или истечения cut-off-time. | повторяемая | - |
| `APPLY_FRAUD_DECISION` | Зафиксировать окончательное решение антифрода: разрешение, запрет или разрешение по cut-off-time при отсутствии ответа. | повторяемая | - |
| `BLOCK_PAYMENT` | Заблокировать подозрительную транзакцию после решения `DENY` и перевести платеж в отказное состояние. | необратимая | - |
| `TRANSFER_TO_COUNTERPARTY` | Перевести деньги контрагенту после успешных проверок или разрешения по cut-off-time. | необратимая | - |

## Допущения

- `Payment Orchestrator` управляет жизненным циклом платежа и хранит состояние Saga, а `Payment Service` выполняет доменные платежные операции.
- `FraudCheck Service` инкапсулирует внутренние антифрод-правила и обращения к внешним проверкам, включая AML/GeoRisk/лимиты, если они нужны для принятия решения.
- Все внешние вызовы выполняются с идемпотентным ключом платежа, поэтому повторная отправка команды не должна создавать дублирующие списания, возвраты, переводы или уведомления.
- Перевод денег контрагенту считается необратимой границей Saga. Если после него потребуется возврат, это уже отдельный бизнес-процесс, а не компенсация текущей Saga.
